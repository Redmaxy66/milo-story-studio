# Streamlined Milo v1

Four inactive operator stages replace the old mandatory implementation topology. This is the non-paid build, not an unattended production service. See D-024 and WORK_ORDER.md.

## What works now

- Explicit week input with five 120-second episode plans, canon release binding, script/continuity review and measured narration requirements.
- A media request contract producing a nested MCP `params` object; approval hashes, budget reservations, ambiguous-response reconciliation and a hard paid lock.
- A shared daily/compilation assembler retaining the owner's compilation model, four reordered bridges, constrained trims, thumbnails and computed chapters.
- Real local FFmpeg finishing with hash-verified approved inputs, source-length checks, frame measurement and hash-bound release review.
- An optional SQLite job/attempt store for one external runner. Optimistic revisions protect jobs; an immediate transaction serializes reservations. The n8n preparer is read-only and is **not** the durable spend lock.

The n8n manual triggers contain clearly synthetic fixtures. The other trigger takes an explicit job from an orchestrator. There is no production schedule, Sheet scan, paid provider node, external rendering endpoint or publishing node in this build. Week Preparation creates a writing brief; it does not call a writing model. Media Queue prepares a candidate request; it does not submit it. Assembly emits a real render manifest for the external runner. Release Package validates a supplied render receipt and human review.

## Operator path

1. Supply the unchanged `03-prompts/MILO_CANON_CONTEXT.md` from canon commit `977755913d9ad41e4f16392d01ea993507af4102`, five briefs and the explicit week ID. Review five scripts together. Never use fixture prose as production content.
2. Obtain actual narration, timed shots and approved asset hashes. Keep the existing approved Milo/reference pack restrictions. Review identities, story continuity, safety and rights. `approvalFor` formats a recorded review; it is not an authentication system or permission to invent human approval. Production inputs must come from the controlled operator/runner.
3. Prepare only missing media. Paid-pilot approval and a versioned provider integration are required before any submission. The current OpenArt configuration is a candidate derived from the handoff; the JSON wrapper is locally tested, but live provider schema acceptance is unproven. No automatic paid retries. Unknown status stops new requests. Durable reservation must precede submission. Poll the existing history ID and reconcile actual charges.
4. Export a daily or compilation job; run the CLI and renderer. Compilation narration files must be approved edits of the daily narration matching the authorised silent-hold removals. The runner refuses audio/video that is shorter than its allocated segment. Editorial review must confirm that no spoken meaning was lost. Still images use a hold; approved video supplies motion. This version does not claim automatic music mixing, lip sync or cinematic camera motion.
5. Review the actual cuts, thumbnail and metadata, then bind approval to the master SHA. Release packaging does not publish or cut over.

## Reproduce the non-paid proof

Run from repository root. Requires installed Node, Python, FFmpeg and ffprobe; no package installation or network.

```sh
node 06-testing/validate_streamlined.mjs
python 06-testing/validate_streamlined_store.py
node 06-testing/fixtures/streamlined/make_fixture.mjs /tmp/milo-synthetic
python 05-code/streamlined/render.py /tmp/milo-synthetic/ep_mon.json --vault /tmp/milo-synthetic --output /tmp/milo-synthetic/renders/ep_mon
python 05-code/streamlined/render.py /tmp/milo-synthetic/compilation.json --vault /tmp/milo-synthetic --output /tmp/milo-synthetic/renders/compilation
node 05-code/streamlined/build_workflows.mjs
```

Render the other four ep_*.json manifests identically, then `node 06-testing/verify_streamlined_renders.mjs /tmp/milo-synthetic`. Existing output directories are refused; use a new version for rerenders. Synthetic binaries are reproducible temporary artifacts, not canon assets. Evidence JSON is versioned.

CLI: `node 05-code/streamlined/cli.mjs prepare|media|assemble|release INPUT.json OUTPUT.json`. Input examples are generated by the fixture builder. A release job has `plan`, `render_result` and `approval`. `runtime_adjustment` is explanatory; only structured `runtime_adjustments` change the timeline. Chapters retain labels and `starts_after` in input and acquire computed numeric starts in output.

## Before cutover

Paid validation must prove provider acceptance, actual charging/reconciliation, durable retrieval, Milo/reference fidelity, approved voice, useful motion and a real finished episode. Then validate a complete five-episode week plus compilation with measured operator effort and spend. Install authenticated durable runner hosting, connect the job store and provider/voice adapters, verify resumability, schedule and rollback. These are explicit remaining production dependencies; the synthetic proof does not establish weekly throughput. Final cutover and public publication require separate owner approval.
